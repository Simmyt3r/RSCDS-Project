01

Import your GitHub repository into Vercel

Go to Add New → Project, select Simmyt3r/RSCDS-Project, and import. Choose Other for Framework Preset, ./ for Root Directory, and public for Output Directory. Leave the Build Command blank.

Open Vercel ↗View source ↗
02

Prepare Aiven using its SQL editor

In Aiven Console open the PostgreSQL service, select PG Studio → SQL editor, paste the project's scripts/schema.sql migration, and click Run selected. It creates only the RSCDS schema and tables. Existing databases must not be erased.

Open Aiven Console ↗View SQL file ↗
03

Add secrets using Vercel's Settings UI

Open Project → Settings → Environment Variables. Create the following variables in Production before deployment. Use encrypted/sensitive fields and the Aiven PostgreSQL URI with SSL enabled.

DATABASE_URLAiven PostgreSQL connection string, server-side onlyADMIN_API_KEYA unique, strong administrator secret, server-side only

This generator never sends or saves the secret. Copy it directly into Vercel's secure environment-variable field. The analysis workflow needs the same secret saved separately under GitHub Actions Secrets.

04

Deploy from the Vercel interface

Click Deploy in Vercel. If you added environment variables after your first deployment, use the Redeploy action from the Vercel Deployments tab. Copy your website URL when it becomes Ready.

Open deployment dashboard ↗
Run the check after deploying. The diagnostic never displays stored secrets.
05

Enable cloud analysis with GitHub Actions

Under repository Settings → Secrets and variables → Actions, add a variable RSCDS_DEPLOY_URL (your HTTPS Vercel website origin) and a secret RSCDS_ADMIN_API_KEY (the same administrator secret). Then open Actions → Manual Satellite Analysis → Run workflow and enter a non-sensitive study area and dates. Results are imported directly into your authenticated database; no public location artifact is uploaded.

GitHub secrets ↗Run analysis ↗
Use a private repository and restricted runner for protected or humanitarian locations. GitHub workflow input values and logs are not a safe place for sensitive coordinates in a public repository.

Privacy and operational limits

This is a research-grade change-candidate detector, not a trained or independently validated temporary-settlement classifier. Do not publicize sensitive locations, publish raw GeoJSON, or infer population/displacement from pixels. Satellite analysis remains a separate worker, not a serverless web request.
