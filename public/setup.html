Browser-first configuration

Set up RSCDS, one step at a time.

This guided setup works in your browser, even if you open the HTML file directly from your computer. No terminal, local PostgreSQL installation, or local model download is required to deploy the website.

Important: The assistant helps you use the official provider dashboards. It cannot access or save your passwords, create provider secrets automatically, or deploy without your account permissions.

Step 1 of 6

Import RSCDS into Vercel

Use Vercel's web interface. Select the existing repository instead of uploading a ZIP.

Choose Import Git Repository → Simmyt3r/RSCDS-Project. Set Framework = Other, Root Directory = ./, Output Directory = public, and leave Build Command blank. Vercel will automatically build new pushes to the main branch.
Open Vercel project import ↗Verify repository ↗

You can proceed before first deployment. Environment variables may also be entered during the Vercel import form.

Step 2 of 6

Check the Aiven spatial database

Your Aiven PostgreSQL service is used for change candidates, review status, and the private analysis queue. The script creates only the rscds schema.

In Aiven Console open your PostgreSQL service → PG Studio → SQL editor. Open scripts/schema.sql, paste the script, and execute it. It uses CREATE IF NOT EXISTS and does not delete other databases.
Open Aiven console ↗View database script ↗
Existing database? If the schema was already successfully applied, you do not need another database. Apply only the missing v0.3 queue migration, or verify readiness after deployment.

Step 3 of 6

Configure server-side secrets

Open Vercel → your project → Settings → Environment Variables. Add the three names below to Production, using Sensitive/Encrypted values. These are never written into RSCDS source files.

DATABASE_URL
Copy the PostgreSQL connection URI from Aiven's connection information. SSL is required. Never paste it into this page.
ADMIN_API_KEY
For unlocking study areas, reviewing candidates and creating jobs.
WORKER_API_KEY
Different from the admin key. Enter this same secret in GitHub Actions in Step 5.
Secrets exist only in these fields until you close or reload this page. Generate, copy, and paste one at a time. Do not save secrets in screenshots, browser bookmarks, GitHub code, or shared messages.

Step 4 of 6

Deploy and inspect the website

In Vercel's Project interface, select Deploy. If you added variables after a deployment, use Deployments → Redeploy. Verify the deployment says Ready.

Open Vercel dashboard ↗
Used only to create convenient links and open a health check. This value is not persisted.
Your application has an in-app Deploy & configure section too. Once deployed, open that tab to see the server's readiness indicators.
Step 5 of 6

Enable automatic satellite analysis

In GitHub → repository Settings → Secrets and variables → Actions, configure:

RSCDS_DEPLOY_URL (Repository variable)

Paste the HTTPS Vercel site origin from Step 4, with no trailing slash and no path.

RSCDS_WORKER_API_KEY (Repository secret)

Paste the same WORKER_API_KEY used in Vercel, not your administrator key.

GitHub Actions settings ↗View analysis workflow ↗
Protection: No coordinates are entered in the public Actions form. Analysis requests are queued through the admin-authenticated site. Use a private repository and trusted worker before studying vulnerable communities or sensitive sites.
Step 6 of 6

Verify the complete setup

Open your deployed project, run the health check, then submit a non-sensitive test AOI through Satellite Imagery → Queue secure analysis. Refresh the analysis jobs list and verify the worker transitions from queued to completed.

Run a queue check in GitHub ↗
Enter your Vercel URL in Step 4 to enable the automated readiness check. On a local file, cross-origin browser protection may prevent direct API checking; use Open health diagnostic instead.
Successful setup requires database = ready, adminConfigured = true, and workerConfigured = true. A successful HTTP response alone is not enough.
